## 🛠️ PASO 1: Actualizar Ingress de SMTP4Dev

### Problema
El ingress de smtp4dev tenía la IP antigua (51.68.114.44).

### Solución

**Archivo:** `smtp4dev-ingress.yaml`

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: smtp4dev-ingress
  namespace: portal
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - host: smtp4dev.51.178.94.25.nip.io
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: smtp4dev
                port:
                  number: 80
```

**Aplicar:**
```bash
kubectl apply -f smtp4dev-ingress.yaml
```

**Resultado:**
- ✅ Accesible en: http://smtp4dev.51.178.94.25.nip.io

## 🚨 PROBLEMA: Pods BPDM en CrashLoopBackOff

### Diagnóstico

```bash
kubectl get pods -n portal | grep bpdm

portal-bpdm-gate-*                    0/1  Running (45 restarts)
portal-bpdm-pool-*                    0/1  CrashLoopBackOff
portal-bpdm-cleaning-service-*        0/1  CrashLoopBackOff
```

**Verificar logs:**
```bash
kubectl logs -n portal portal-bpdm-gate-* --tail=30

# Error encontrado:
Caused by: java.net.UnknownHostException: centralidp.tx.test
```

### Root Cause

Los ConfigMaps de BPDM tenían **dos problemas**:

1. **URLs con `tx.test`**: Los ConfigMaps contenían URLs de test en lugar de las URLs reales con la IP del LoadBalancer
2. **URLs externas**: Los servicios BPDM intentaban comunicarse usando URLs externas (a través de Ingress) en lugar de servicios internos del cluster

## 🛠️ PASO 7: Corrección Problema 2 - URLs Externas a Internas

### Problema

Los pods BPDM intentaban comunicarse entre sí usando URLs externas:

```yaml
# ❌ INCORRECTO - Comunicación externa (a través de Ingress)
orchestrator:
  base-url: http://business-partners.51.178.94.25.nip.io/orchestrator

pool:
  base-url: http://business-partners.51.178.94.25.nip.io/pool
```

Esto causaba:
- ❌ Dependencia del Ingress/LoadBalancer
- ❌ Latencia adicional
- ❌ Timeouts durante startup

### Solución: URLs Internas (ClusterIP Services)

```yaml
# ✅ CORRECTO - Comunicación interna del cluster
orchestrator:
  base-url: http://portal-bpdm-orchestrator:80

pool:
  base-url: http://portal-bpdm-pool:80
```

### Comandos de Corrección

**Comando 1: Pool → Orchestrator**
```bash
kubectl get configmap portal-bpdm-pool -n portal -o json \
  | jq '.data."deployment.yml" |= gsub("http://business-partners.51.178.94.25.nip.io/orchestrator"; "http://portal-bpdm-orchestrator:80")' \
  | kubectl apply -f -
```

**Comando 2: Gate → Orchestrator + Pool**
```bash
kubectl get configmap portal-bpdm-gate -n portal -o json \
  | jq '.data."deployment.yml" |= gsub("http://business-partners.51.178.94.25.nip.io/orchestrator"; "http://portal-bpdm-orchestrator:80") | .data."deployment.yml" |= gsub("http://business-partners.51.178.94.25.nip.io/pool"; "http://portal-bpdm-pool:80")' \
  | kubectl apply -f -
```

**Comando 3: Cleaning Service → Orchestrator**
```bash
kubectl get configmap portal-bpdm-cleaning-service-dummy -n portal -o json \
  | jq '.data."deployment.yml" |= gsub("http://business-partners.51.178.94.25.nip.io/orchestrator"; "http://portal-bpdm-orchestrator:80")' \
  | kubectl apply -f -
```

### Verificar Cambios

```bash
kubectl get configmap portal-bpdm-pool -n portal -o yaml | grep "base-url"
# Resultado: base-url: http://portal-bpdm-orchestrator:80  ✅

kubectl get configmap portal-bpdm-gate -n portal -o yaml | grep "base-url"
# Resultado: 
#   base-url: http://portal-bpdm-orchestrator:80  ✅
#   base-url: http://portal-bpdm-pool:80  ✅
```

## 📝 Lecciones Aprendidas

### 1. ConfigMaps y Helm

- Helm **no actualiza ConfigMaps existentes** automáticamente en algunos casos
- Es necesario patchear ConfigMaps manualmente o hacer `helm upgrade --force`
- Usar `kubectl + jq` es más seguro que `sed` para modificar ConfigMaps

### 2. URLs Internas vs Externas

**URLs Externas** (para acceso desde browser):
```yaml
portal:
  bpdm:
    poolAddress: "http://business-partners.51.178.94.25.nip.io"
```

**URLs Internas** (para comunicación entre pods):
```yaml
bpdm-pool:
  applicationConfig:
    bpdm:
      orchestrator:
        baseUrl: "http://portal-bpdm-orchestrator:80"
```

### 3. Orden de Reinicio

Siempre respetar el orden de dependencias:
1. Servicios base (orchestrator)
2. Servicios dependientes (pool, cleaning-service)
3. Servicios finales (gate)

### 4. Timeouts de Startup

Los pods BPDM tienen init containers con delays significativos:
- Init container: ~60-90 segundos
- Startup del pod: ~30-60 segundos
- **Total: 90-150 segundos por pod**

### 5. Verificación de Ingress

Siempre verificar que los ingress tienen:
- ✅ `ingressClassName: nginx`
- ✅ `ADDRESS` asignada (IP del LoadBalancer)
- ✅ Host correcto con la IP actual
