## Introducción

El Portal de Catena-X está diseñado con una arquitectura modular que permite diferentes niveles de personalización:

- **Frontend**: React + TypeScript (portal-frontend, portal-frontend-registration)
- **Assets**: Recursos estáticos (imágenes, logos, documentación)
- **Backend**: .NET C# (portal-backend)

**✅ Conclusión**: **SÍ es factible personalizar el portal** a través de múltiples métodos dependiendo de tus necesidades.

## Niveles de Personalización

## Opción 1: Configuración Básica (Sin Código)

### ✨ Ventajas
- No requiere conocimientos de programación
- Cambios mediante valores de Helm
- Fácil de mantener y actualizar

### 📝 Configuraciones Disponibles

#### Información del Operador

> **⚠️ IMPORTANTE**: El `operator` es el **administrador/operador del dataspace Catena-X**, NO las empresas que hacen onboarding.
> 
> - **Operator = Tú** (quien gestiona la instancia del portal)
> - Corresponde al tenant **CX-Operator** en Keycloak
> - Usuario administrador: `cx-operator@tx.test` (o tu dominio)
> - Las empresas que pasan por onboarding (Ikerlan, Assembly, etc.) son **participantes/partners**, no el operator

**Operator (CX-Operator)**
- 🏢 **Quién es**: La organización que **gestiona y administra** la instancia del portal Catena-X

## Opción 2: Personalización Visual (Theme/Assets)

### 🎨 Qué Puedes Personalizar

- **Logos**: Logo principal, favicon, logo de empresa
- **Imágenes**: Imágenes de landing page, banners, iconos
- **Colores**: Theme colors, paleta de colores
- **Estilos**: CSS personalizado, fuentes
- **Documentación**: Archivos de ayuda y documentación

### 📂 Repositorios Relevantes

| Componente | Repositorio | Contenido |
|------------|-------------|-----------|
| **Frontend** | https://github.com/eclipse-tractusx/portal-frontend | Aplicación React principal |
| **Assets** | https://github.com/eclipse-tractusx/portal-assets | Logos, imágenes, documentación |
| **Shared Components** | https://github.com/eclipse-tractusx/portal-shared-components | Componentes UI reutilizables |
| **Registration** | https://github.com/eclipse-tractusx/portal-frontend-registration | Frontend de registro |

### 🔧 Proceso de Personalización

#### Paso 1: Fork del Repositorio

```bash
# En GitHub, hacer fork de:
# https://github.com/eclipse-tractusx/portal-assets
# o
# https://github.com/eclipse-tractusx/portal-frontend

# Clonar tu fork
git clone https://github.com/TU_USUARIO/portal-assets.git
cd portal-assets
```

#### Paso 2: Modificar Assets

```bash
# Estructura típica de assets
portal-assets/
├── public/
│   ├── assets/
│   │   ├── logo/
│   │   │   ├── logo-principal.svg
│   │   │   ├── favicon.ico
│   │   │   └── logo-dark.svg
│   │   ├── images/
│   │   │   ├── landing-hero.png
│   │   │   └── feature-*.png
│   │   └── styles/
│   │       └── custom-theme.css
│   └── documentation/
│       └── *.md
└── src/
    └── assets/
        └── locales/
            ├── en/
            └── de/

# Reemplazar tus archivos
cp tu-logo.svg public/assets/logo/logo-principal.svg
cp tu-favicon.ico public/assets/logo/favicon.ico
```

#### Paso 3: Build Imagen Docker

**Opción A - Dockerfile del repositorio oficial:**

```dockerfile
# Usar el Dockerfile existente en el repositorio
# Ejemplo: portal-assets/.conf/Dockerfile

# Build
docker build -f .conf/Dockerfile -t tu-registry.io/portal-assets:custom-v1 .

# Push a tu registry
docker push tu-registry.io/portal-assets:custom-v1
```

**Opción B - Crear tu propio Dockerfile:**

```dockerfile
FROM docker.io/tractusx/portal-assets:v2.5.0

# Copiar tus assets personalizados
COPY ./custom-assets/logo/ /app/assets/logo/
COPY ./custom-assets/images/ /app/assets/images/
COPY ./custom-theme.css /app/assets/styles/

# Exponer puerto
EXPOSE 8080

CMD ["nginx", "-g", "daemon off;"]
```

#### Paso 4: Actualizar Values de Helm

```yaml
# Crear: values-custom-assets.yaml
frontend:
  assets:
    image:
      name: "tu-registry.io/portal-assets"
      assetstag: "custom-v1"
      pullPolicy: "Always"
    # Si usas registry privado
    pullSecrets:
      - name: tu-registry-secret

  portal:
    image:
      # Opcional: también personalizar frontend
      name: "tu-registry.io/portal-frontend"
      portaltag: "custom-v1"
```

#### Paso 5: Desplegar

```bash
helm upgrade portal charts/umbrella \
  -f charts/umbrella/values-adopter-portal-for-onboarding.yaml \
  -f charts/umbrella/values-ovh-hosts-portal.yaml \
  -f values-custom-assets.yaml \
  -n portal

# Verificar
kubectl get pods -n portal | grep assets
kubectl logs -n portal <pod-assets> -f
```

### 🎨 Personalización de Temas

El portal usa temas de Keycloak y Material-UI. Para personalizar:

#### Theme de Login (Keycloak)

```yaml
# En values de centralidp/sharedidp
centralidp:
  keycloak:
    extraVolumes:
      - name: custom-theme
        configMap:
          name: custom-keycloak-theme
    extraVolumeMounts:
      - name: custom-theme
        mountPath: /opt/bitnami/keycloak/themes/custom-theme

# Crear ConfigMap con tu theme
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: custom-keycloak-theme
data:
  theme.properties: |
    parent=keycloak.v2
    import=common/keycloak
  login.css: |
    .login-pf body {
      background: url('../img/tu-background.jpg');
    }
```

#### Theme de Aplicación (Material-UI)

```typescript
// En portal-frontend/src/theme.tsx
import { createTheme } from '@mui/material/styles';

export const theme = createTheme({
  palette: {
    primary: {
      main: '#0088CC',  // Tu color principal
    },
    secondary: {
      main: '#FF6600',  // Tu color secundario
    },
  },
  typography: {
    fontFamily: '"Roboto", "Helvetica", "Arial", sans-serif',
  },
});
```

### ⚠️ Consideraciones

- Requiere conocimientos de desarrollo (React, TypeScript, .NET)
- Mayor esfuerzo de mantenimiento
- Necesitas mantener sincronizado con upstream para patches de seguridad
- Recomendado solo si necesitas funcionalidad no disponible

### 📚 Repositorios a Considerar

| Componente | Repositorio | Tecnología |

## Caso Práctico: Cambiar Logos e Imágenes

### 🎯 Objetivo
Reemplazar el logo de Catena-X por el logo de tu empresa.

### 📋 Método Recomendado: Personalizar Assets

#### Paso 1: Preparar Tus Assets

```bash
# Estructura de archivos a preparar
custom-assets/
├── logo-principal.svg          # Logo principal (fondo claro)
├── logo-principal-dark.svg     # Logo para tema oscuro
├── favicon.ico                 # Favicon 32x32
├── favicon-16x16.png          # Favicon pequeño
├── favicon-32x32.png          # Favicon mediano
└── apple-touch-icon.png       # Icon para iOS 180x180
```

**Especificaciones recomendadas:**
- Logo principal: SVG vectorial o PNG 200x50px (transparente)
- Favicon: ICO 32x32px o PNG múltiples tamaños
- Apple touch icon: PNG 180x180px

#### Paso 2: Fork y Modificación

```bash
# Fork en GitHub de:
# https://github.com/eclipse-tractusx/portal-assets

# Clonar
git clone https://github.com/TU_USUARIO/portal-assets.git
cd portal-assets

# Crear rama para cambios
git checkout -b feature/custom-branding

# Copiar tus assets
cp ~/custom-assets/logo-principal.svg public/assets/logo/
cp ~/custom-assets/favicon.ico public/
cp ~/custom-assets/apple-touch-icon.png public/

# Modificar referencias si es necesario
# En: public/index.html
vim public/index.html
```

#### Paso 3: Build Imagen

```bash
# Opción A: Usar Dockerfile del repo
docker build -f .conf/Dockerfile \
  -t tu-registry.io/portal-assets:branding-v1 .

# Opción B: Dockerfile personalizado simple
cat > Dockerfile.custom << 'EOF'
FROM nginx:alpine

# Copiar assets personalizados
COPY public/ /usr/share/nginx/html/

# Configuración nginx
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 8080
CMD ["nginx", "-g", "daemon off;"]
EOF

docker build -f Dockerfile.custom \
  -t tu-registry.io/portal-assets:branding-v1 .

# Push
docker push tu-registry.io/portal-assets:branding-v1
```

#### Paso 4: Actualizar Deployment

```yaml
# Crear: values-branding.yaml
frontend:
  assets:
    image:
      name: "tu-registry.io/portal-assets"
      assetstag: "branding-v1"
      pullPolicy: "Always"
```

```bash
# Aplicar
helm upgrade portal charts/umbrella \
  -f charts/umbrella/values-adopter-portal-for-onboarding.yaml \
  -f charts/umbrella/values-ovh-hosts-portal.yaml \
```

#### Paso 5: Verificación en Browser

1. Abrir `http://portal.51.83.111.178.nip.io` (tu URL)
2. Limpiar caché del navegador (Ctrl+Shift+R)

### 🔄 Alternativa: ConfigMap para Assets Pequeños

Si solo necesitas cambiar pocos archivos:

```yaml
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: custom-portal-assets
  namespace: portal
binaryData:
  logo-principal.svg: |
    <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 200 50">
      <!-- Tu SVG aquí -->
    </svg>
---
# Añadir volume al deployment de assets
spec:
  template:
    spec:
      volumes:
        - name: custom-logo
          configMap:
            name: custom-portal-assets
      containers:
        - name: assets
          volumeMounts:
            - name: custom-logo
              mountPath: /usr/share/nginx/html/assets/logo/logo-principal.svg
              subPath: logo-principal.svg
```

## Gestión de Actualizaciones

### 🔄 Mantener Fork Actualizado

```bash
# Configurar upstream (una sola vez)
cd portal-frontend
git remote add upstream https://github.com/eclipse-tractusx/portal-frontend.git

# Sincronizar periódicamente
git fetch upstream
git checkout main
git merge upstream/main

# Resolver conflictos si los hay
git status
# ... editar archivos conflictivos
git add .
git commit -m "merge: sync with upstream v2.6.0"

# Actualizar tu rama de desarrollo
git checkout feature/custom-branding
git rebase main
```

### 📦 Actualizar Versiones del Chart

```bash
# Ver versión actual
helm list -n portal

# Ver nuevas versiones disponibles
helm repo update
helm search repo portal --versions | head

# Actualizar manteniendo personalizaciones
helm upgrade portal tractusx-dev/portal \
  --version 2.6.0 \
  -f charts/umbrella/values-adopter-portal-for-onboarding.yaml \
  -f charts/umbrella/values-ovh-hosts-portal.yaml \
  -f values-custom-assets.yaml \
  -n portal

# Verificar
kubectl get pods -n portal
kubectl logs -n portal <pod-name>
```

### 🔐 Security Updates

```bash
# Monitorear security advisories
# https://github.com/eclipse-tractusx/portal/security/advisories

# Subscribirse a notificaciones en GitHub
# Watch → Custom → Security alerts

# Aplicar patches críticos inmediatamente
git fetch upstream
git checkout -b security/CVE-2024-XXXX
git cherry-pick <commit-hash-from-upstream>
git push origin security/CVE-2024-XXXX

# Build y deploy urgente
docker build -t tu-registry.io/portal-frontend:security-patch-1 .
docker push tu-registry.io/portal-frontend:security-patch-1
kubectl set image deployment/portal-frontend \
  portal=tu-registry.io/portal-frontend:security-patch-1 \
  -n portal
```

## Recomendaciones

### ✅ Mejores Prácticas

#### 1. Estrategia de Personalización

**Para Cambios Mínimos** (logos, colores, textos):
- ✅ Fork solo de `portal-assets`
- ✅ Mantén `portal-frontend` y `portal-backend` oficiales
- ✅ Fácil de actualizar

**Para Cambios Medios** (funcionalidad UI limitada):
- ✅ Fork de `portal-frontend` + `portal-assets`
- ⚠️ Mantén `portal-backend` oficial si es posible
- ⚠️ Requiere testing en cada actualización

**Para Cambios Profundos** (nueva funcionalidad):
- ⚠️ Fork completo: frontend, backend, assets
- ❌ Alto esfuerzo de mantenimiento
- ❌ Considera contribuir al proyecto upstream

#### 2. Gestión de Imágenes Docker

```bash
# Estrategia de tags recomendada
tu-registry.io/portal-assets:v2.5.0-custom1      # Basado en versión oficial
tu-registry.io/portal-assets:v2.5.0-custom2      # Iteraciones
tu-registry.io/portal-assets:latest-custom       # Latest de tu custom
tu-registry.io/portal-assets:prod                # Producción estable

# Usar tags inmutables en producción
frontend:
  assets:
    image:
      name: "tu-registry.io/portal-assets"
      assetstag: "v2.5.0-custom1"  # NO usar 'latest'
```

#### 3. Documentación

```bash
# Mantener CHANGELOG.md en tu fork
# CHANGELOG-CUSTOM.md

## [2.5.0-custom1] - 2026-01-30
### Added
- Logo personalizado de la empresa
- Colores corporativos en theme

### Changed
- Modificado landing page con información de la empresa

### Security
- Aplicado patch de seguridad de upstream

## [2.5.0-base]
- Basado en portal-assets v2.5.0 oficial
```

#### 4. Testing

```bash
# Antes de desplegar en producción

# 1. Test local con Docker
docker run -p 8080:8080 tu-registry.io/portal-assets:test
curl http://localhost:8080/assets/logo/logo-principal.svg

# 2. Deploy en namespace de test
helm install portal-test charts/umbrella \
  -f values-test.yaml \
  -n portal-test --create-namespace

# 3. Tests automatizados (si aplica)
cd portal-frontend
yarn test
yarn e2e

# 4. Verificación manual
# - Login funciona
# - Logo aparece correctamente
# - No hay errores en consola del navegador
# - Responsive funciona (mobile, tablet)
```

#### 5. Rollback Plan

```bash
# Guardar versión anterior antes de actualizar
helm get values portal -n portal > values-backup-$(date +%Y%m%d).yaml

# En caso de problemas, rollback
helm rollback portal -n portal

# O volver a versión específica
helm rollback portal 3 -n portal  # Rollback a revision 3

# Verificar historial
helm history portal -n portal
```

### ⚠️ Qué NO Hacer

❌ **NO modifiques código directamente en el cluster** (vía `kubectl edit`)
❌ **NO uses tag `latest`** en producción
❌ **NO guardes secretos en el código** (usa secrets, variables de entorno)
❌ **NO ignores security updates** del proyecto upstream
❌ **NO despligues sin probar** en entorno de test primero
❌ **NO pierdas track de tus cambios** (usa git, documenta)

### 💡 Próximos Pasos Sugeridos

Para empezar con personalización:

1. **Cambios Mínimos (Recomendado para empezar)**:
   ```bash
   # Editar operator info (información de Assembly como operador del dataspace)
   vim charts/umbrella/values-ovh-hosts-portal.yaml
   # Añadir sección operator: con información de Assembly
   
   # Ejemplo:
   operator:
     bpn: "BPNL00000003ASSM"  # BPN de Assembly
     name: "Assembly Technologies"
     shortname: "Assembly"
     city: "Donostia-San Sebastián"
     country_alpha2code: "ES"
   ```

2. **Cambios Visuales**:
   - Fork de portal-assets en tu GitHub
   - Modificar logos y assets
   - Build y push imagen custom
   - Crear values-custom-assets.yaml

3. **Testing**:
   - Crear namespace `portal-test` para pruebas
   - Deploy con tus cambios
   - Verificar funcionamiento
   - Promover a producción
