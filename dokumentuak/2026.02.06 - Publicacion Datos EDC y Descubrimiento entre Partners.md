## Problema 1: Publicación de Datos - Corrección

### ❌ Lo que NO existe

En el documento anterior mencioné incorrectamente:
```
Portal → Data Catalog → Assets → Create New Asset
```

**Esta interfaz NO EXISTE en el Portal de Catena-X.**

### ✅ La Realidad

- El Portal Web de Catena-X es para:
  - ✅ Onboarding de compañías
  - ✅ Gestión de usuarios
  - ✅ Registro de conectores
  - ✅ Ver aplicaciones disponibles
  - ❌ **NO para gestión de Assets/Datos**

- La gestión de datos (Assets, Policies, Contracts) se hace **directamente contra la Management API del EDC**, no desde el Portal

## Paso a Paso: MondragonAssembly Publica Datos

### 1. Crear un Asset (Datos a Compartir)

Un **Asset** representa los datos que quieres compartir. Puede ser:
- Un endpoint REST API
- Archivos en S3/Storage
- Datos en una base de datos
- Streaming de datos

**Ejemplo: MondragonAssembly publica datos de producción**

```bash
# Variables
MASS_MGMT_API="https://edc-mass-control.51.178.94.25.nip.io/management"
MASS_API_KEY="mass-api-key-change-in-production"

# Crear Asset
curl -X POST "${MASS_MGMT_API}/v3/assets" \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ${MASS_API_KEY}" \
  -d '{
    "@context": {
      "tx": "https://w3id.org/tractusx/v0.0.1/ns/",
      "edc": "https://w3id.org/edc/v0.0.1/ns/"
    },
    "@id": "mass-production-data-001",
    "properties": {
      "name": "Production Data - Assembly Line A",
      "description": "Real-time production metrics from assembly line A",
      "contenttype": "application/json",
      "version": "1.0"
    },
    "dataAddress": {
      "@type": "DataAddress",
      "type": "HttpData",
      "baseUrl": "http://mass-backend.mass-connector.svc.cluster.local:8080/api/production/line-a",
      "proxyMethod": "true",
      "proxyPath": "true"
    }
  }'
```

**Respuesta esperada:**
```json
{
  "@id": "mass-production-data-001",
  "createdAt": 1707235200000
}
```

**⚠️ Importante sobre `baseUrl`:**
- Debe apuntar a tu backend real que sirve los datos
- Puede ser:
  - URL interna del cluster: `http://mass-backend.mass-connector.svc.cluster.local:8080/api/data`
  - URL externa: `https://api.mondragon-assembly.com/production/data`
  - Endpoint de prueba temporalmente: `http://httpbin.org/json`

### 3. Crear una Policy (Define Quién Puede Acceder)

Las **Policies** definen las reglas de acceso:
- ¿Quién puede acceder? (BPN específico, cualquiera, grupo)
- ¿Bajo qué condiciones?
- ¿Con qué propósito?

**Ejemplo: Solo Ikerlan puede acceder**

```bash
# Crear Policy que solo permite acceso a Ikerlan
curl -X POST "${MASS_MGMT_API}/v3/policydefinitions" \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ${MASS_API_KEY}" \
  -d '{
    "@context": {
      "odrl": "http://www.w3.org/ns/odrl/2/",
      "edc": "https://w3id.org/edc/v0.0.1/ns/"
    },
    "@id": "mass-policy-ikerlan-only",
    "policy": {
      "@type": "odrl:Set",
      "odrl:permission": [
        {
          "odrl:action": "USE",
          "odrl:constraint": {
            "odrl:leftOperand": "BusinessPartnerNumber",
            "odrl:operator": "EQ",
            "odrl:rightOperand": "BPNL00000002IKLN"
          }
        }
      ]
    }
  }'
```

**Ejemplo: Cualquiera puede acceder (sin restricciones)**

```bash
curl -X POST "${MASS_MGMT_API}/v3/policydefinitions" \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ${MASS_API_KEY}" \
  -d '{
    "@context": {
      "odrl": "http://www.w3.org/ns/odrl/2/",
      "edc": "https://w3id.org/edc/v0.0.1/ns/"
    },
    "@id": "mass-policy-unrestricted",
    "policy": {
      "@type": "odrl:Set",
      "odrl:permission": [
        {
          "odrl:action": "USE"
        }
      ]
    }
  }'
```

### 5. Crear Contract Definition (Vincula Asset + Policy)

Un **Contract Definition** combina:
- Qué datos ofreces (Asset)
- Bajo qué condiciones (Access Policy)
- Qué puede hacer con ellos (Contract Policy)

```bash
# Crear Contract Definition
curl -X POST "${MASS_MGMT_API}/v3/contractdefinitions" \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ${MASS_API_KEY}" \
  -d '{
    "@context": {
      "edc": "https://w3id.org/edc/v0.0.1/ns/"
    },
    "@id": "mass-contract-001",
    "accessPolicyId": "mass-policy-ikerlan-only",
    "contractPolicyId": "mass-policy-ikerlan-only",
    "assetsSelector": [
      {
        "@type": "CriterionDto",
        "operandLeft": "https://w3id.org/edc/v0.0.1/ns/id",
        "operator": "=",
        "operandRight": "mass-production-data-001"
      }
    ]
  }'
```

**Respuesta esperada:**
```json
{
  "@id": "mass-contract-001",
  "createdAt": 1707235500000
}
```

### 6. Verificar Contract Definition


## Problema 2: Partners No se Descubren

### ¿Por qué Ikerlan no ve a MondragonAssembly?

El descubrimiento de partners en Catena-X requiere varios componentes funcionando:

```
┌──────────────────────────────────────────────────────────┐
│              DESCUBRIMIENTO EN CATENA-X                   │
└──────────────────────────────────────────────────────────┘

1. Discovery Finder
   ├─ URL: http://semantics.51.178.94.25.nip.io/discoveryfinder
   └─ Función: "¿Dónde busco endpoints para un BPN?"

2. BPN Discovery Service  
   ├─ URL: http://semantics.51.178.94.25.nip.io/bpndiscovery
   └─ Función: "¿Qué BPN corresponde a este identificador?"

3. EDC Discovery Service (BDRS)
   ├─ URL: http://bdrs-server.portal.svc.cluster.local:8080
   └─ Función: "¿Cuál es el endpoint DSP del conector de este BPN?"

4. Connector Self-Description
   └─ Función: Cada conector debe anunciarse en BDRS
```

### Verificar si Discovery Está Desplegado

```bash
# 1. Verificar Discovery Finder
kubectl get pods -n portal | grep discovery

# 2. Verificar servicios
kubectl get svc -n portal | grep -E "discovery|bdrs"

# 3. Verificar ingress
kubectl get ingress -n portal | grep -E "discovery|semantics"
```

**Esperado:**
```
discoveryfinder-xxx        1/1   Running
bpndiscovery-xxx          1/1   Running
bdrs-server-xxx           1/1   Running
```


## Solución: Configurar Discovery

### Paso 1: Registrar Conectores en BDRS

Los conectores deben registrarse en el **BPN Discovery Registry Service (BDRS)**.

**Desde dentro del cluster:**

```bash
# Acceder a un pod que tenga curl
kubectl exec -it -n portal deployment/portal-backend -c backend -- bash

# Una vez dentro, registrar MondragonAssembly
curl -X POST http://bdrs-server.portal.svc.cluster.local:8080/api/v1/directory \
  -H "Content-Type: application/json" \
  -d '{
    "bpn": "BPNL00000000MASS",
    "type": "ProtocolEndpoint",
    "description": "MondragonAssembly EDC Connector",
    "endpoint": "https://edc-mass-control.51.178.94.25.nip.io/api/v1/dsp",
    "endpointProtocol": "dataspace-protocol-http",
    "endpointProtocolVersion": ["0.8"]
  }'

# Registrar Ikerlan
curl -X POST http://bdrs-server.portal.svc.cluster.local:8080/api/v1/directory \
  -H "Content-Type: application/json" \
  -d '{
    "bpn": "BPNL00000002IKLN",
    "type": "ProtocolEndpoint",
    "description": "Ikerlan EDC Connector",
    "endpoint": "https://edc-ikln-control.51.178.94.25.nip.io/api/v1/dsp",
    "endpointProtocol": "dataspace-protocol-http",
    "endpointProtocolVersion": ["0.8"]
  }'
```

```bash
#!/bin/bash

echo "=== Ikerlan consulta el catálogo de MondragonAssembly ==="

IKLN_MGMT_API="https://edc-ikln-control.51.178.94.25.nip.io/management"
IKLN_API_KEY="ikln-api-key-change-in-production"
MASS_DSP_URL="https://edc-mass-control.51.178.94.25.nip.io/api/v1/dsp"

# Consultar catálogo
curl -X POST "${IKLN_MGMT_API}/v3/catalog/request" \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: ${IKLN_API_KEY}" \
  -d "{
    \"@context\": {
      \"edc\": \"https://w3id.org/edc/v0.0.1/ns/\"
    },
    \"counterPartyAddress\": \"${MASS_DSP_URL}\",
    \"protocol\": \"dataspace-protocol-http\"
  }" | jq

echo ""
echo "Deberías ver el asset: mass-production-data-001"
echo "Y la policy que permite acceso solo a Ikerlan (BPNL00000002IKLN)"
```

**Ejecutar:**
```bash
chmod +x ikln-query-mass-catalog.sh
./ikln-query-mass-catalog.sh
```

**Output esperado:**
```json
{
  "@id": "catalog-id",
  "@type": "dcat:Catalog",
  "dcat:dataset": [
    {
      "@id": "mass-production-data-001",
      "@type": "dcat:Dataset",
      "dcat:description": "Real-time production metrics from assembly line A",
      "odrl:hasPolicy": {
        "@id": "mass-policy-ikerlan-only",
        "odrl:permission": [{
          "odrl:constraint": {
            "odrl:leftOperand": "BusinessPartnerNumber",
            "odrl:operator": "EQ",
            "odrl:rightOperand": "BPNL00000002IKLN"
          }
        }]
      }
    }
  ]
}
```

## Troubleshooting

### Problema: Assets no aparecen en catálogo

**Verificar:**
```bash
# 1. Asset existe
curl -X GET "${MASS_MGMT_API}/v3/assets/mass-production-data-001" \
  -H "X-Api-Key: ${MASS_API_KEY}" | jq

# 2. Policy existe
curl -X GET "${MASS_MGMT_API}/v3/policydefinitions/mass-policy-ikerlan-only" \
  -H "X-Api-Key: ${MASS_API_KEY}" | jq

# 3. Contract Definition existe
curl -X GET "${MASS_MGMT_API}/v3/contractdefinitions/mass-contract-001" \
  -H "X-Api-Key: ${MASS_API_KEY}" | jq
```

### Problema: "Forbidden" al consultar catálogo

**Causa:** Identidad no configurada correctamente (IATP, DIM, Verifiable Credentials)

**Verificar:**
```bash
# Ver logs del Control Plane
kubectl logs -n mass-connector deployment/edc-mass-tractusx-connector-controlplane --tail=100

# Buscar errores de autenticación
kubectl logs -n mass-connector deployment/edc-mass-tractusx-connector-controlplane | grep -i "auth\|credential\|iatp"
```

### Problema: Partner no aparece en BDRS

**Re-registrar:**
```bash
# Eliminar registro anterior (si existe)
kubectl exec -n portal deployment/portal-backend -c backend -- \
  curl -X DELETE http://bdrs-server.portal.svc.cluster.local:8080/api/v1/directory/BPNL00000000MASS

# Registrar de nuevo
./register-connectors-bdrs.sh
```
