# 2026-02-04 - Corrección Partner Network Vacío - Análisis y Solución

## 📋 Resumen Ejecutivo

**Fecha:** 4 de Febrero de 2026  
**Cluster:** OVH Kubernetes (51.178.94.25.nip.io)  
**Namespace:** portal  
**Problema:** Vista "Partner Network" aparece vacía a pesar de tener partners en estado ACTIVE  
**Partners Afectados:** MondragonAssembly (BPNL00000000MASS), Ikerlan (BPNL00000002IKLN)  
**Estado:** ✅ **RESUELTO** - Configurada variable de entorno BPDM_POOL_API_URL

## ✅ Solución Final (La Que Funcionó)

**Causa raíz:** Frontend de Portal intentaba llamar a `http://portal-bpdm-pool` (servicio interno de Kubernetes) desde el navegador del usuario, causando error `ERR_NAME_NOT_RESOLVED`.

**Solución aplicada:**
```bash
kubectl set env deployment/portal-portal -n portal \
  BPDM_POOL_API_URL="http://business-partners.51.178.94.25.nip.io/pool/v6" \
  BPDM_GATE_API_URL="http://business-partners.51.178.94.25.nip.io/gate"
```

**Resultado:** ✅ Partner Network ahora muestra MondragonAssembly e Ikerlan correctamente

## 💡 Lecciones Aprendidas

### 1. Frontend vs Backend - Diferente Arquitectura

**Backend** (Portal Services):
- Corre dentro del cluster Kubernetes
- Usa nombres internos de servicios (ej: `portal-bpdm-pool`)
- Variables de entorno configuradas en Helm values: `portal.bpdm.poolAddress`

**Frontend** (React App):
- Corre en el navegador del usuario
- **NO puede** resolver nombres internos de Kubernetes
- Necesita URLs públicas (ingress)
- Variables de entorno configuradas en: `portal.frontend.portal.env`

### 2. React Apps - Configuración en Build Time vs Runtime

**Problema original:** Intentar usar Helm values que solo aplican al backend

**Solución:** React apps compiladas pueden leer env vars en runtime mediante script de inyección en `index.html`:

```html
<script>
  const ENV = {
    BPDM_POOL_API_URL: process.env.BPDM_POOL_API_URL || "default",
    ...
  }
</script>
```

Portal Frontend de Tractus-X **SÍ soporta** esta funcionalidad, pero NO estaba configurada en el despliegue.

### 3. Debugging Frontend - DevTools es Fundamental

**Herramientas clave:**
- **Network tab:** Ver llamadas HTTP, status codes, responses
- **Console tab:** Ver errores JavaScript
- **Application tab:** Ver variables de entorno cargadas

**Error identificado:** `net::ERR_NAME_NOT_RESOLVED` → Nombre DNS no resuelve

### 4. Helm Upgrades - Preservar Correcciones Manuales

**Problema:** `kubectl set env` modifica el deployment, pero se pierde en el próximo `helm upgrade`

**Solución:** Documentar correcciones manuales en archivo values dedicado:
- `values-ovh-manual-fixes.yaml`
- Incluir en todos los futuros upgrades
