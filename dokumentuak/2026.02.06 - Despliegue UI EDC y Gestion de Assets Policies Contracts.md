## Problemas Encontrados y Soluciones

### Problema 1: Certificados TLS Auto-firmados

**Error**:
```
No connector found at https://edc-mass-control.51.178.94.25.nip.io/management
```

**Logs del contenedor**:
```
API proxy error: TypeError: fetch failed
  [cause]: [Error: self-signed certificate] { code: 'DEPTH_ZERO_SELF_SIGNED_CERT' }
```

**Causa**: 
- Los Ingress de los conectores tienen TLS habilitado con certificados auto-firmados generados por nginx-ingress
- Node.js rechaza por defecto certificados no válidos

**Solución**:
Añadir variable de entorno en `k8s/deployment.yaml`:

```yaml
env:
- name: NODE_TLS_REJECT_UNAUTHORIZED
  value: "0"
```

```bash
# Aplicar cambios
kubectl apply -f k8s/deployment.yaml -n edc-ui
kubectl rollout status deployment/edc-ui -n edc-ui
```

### Problema 2: API Keys Incorrectos

**Error**:
```
Response status: 401
[{"message":"Request could not be authenticated","type":"AuthenticationFailed"}]
```

**Logs del contenedor**:
```
Using API key for connector https://edc-mass-control.51.178.94.25.nip.io/management: TEST1
```

**Causa**:
El archivo `edc-config.ts` tenía hardcodeado `TEST1` como API key por defecto, pero los conectores requieren:
- MASS: `mass-api-key-change-in-production`
- IKLN: `ikln-api-key-change-in-production`

**Solución**:

#### 1. Modificar `edc-config.ts`

```typescript
// edc-config.ts

export const authConfig = {
  apiKey: "mass-api-key-change-in-production", // Default API key for MASS connector
}

// Configuración de conectores por defecto
export const connectorDefaults = {
  provider: "https://edc-mass-control.51.178.94.25.nip.io/management", 
  consumer: "https://edc-ikln-control.51.178.94.25.nip.io/management", 
}

// Configuración general de la aplicación
export const appConfig = {
  flDataAppEnabled: true,
}

// Catálogo de conectores
export const connectorCatalog = [
  {
    name: "MondragonAssembly Connector",
    address: "https://edc-mass-control.51.178.94.25.nip.io/management",
    id: "BPNL00000000MASS",
    description: "Conector EDC de MondragonAssembly",
    type: "provider",
    apiKey: "mass-api-key-change-in-production",
  },
  {
    name: "Ikerlan Connector",
    address: "https://edc-ikln-control.51.178.94.25.nip.io/management",
    id: "BPNL00000000IKLN",
    description: "Conector EDC de Ikerlan",
    type: "consumer",
    apiKey: "ikln-api-key-change-in-production",
  },
]

// Función para obtener la clave de API para un conector específico
export const getApiKeyForConnector = (connectorAddress: string): string => {
  const connector = connectorCatalog.find(
    (c) => c.address === connectorAddress || connectorAddress.startsWith(c.address),
  )

  if (connector && connector.apiKey) {
    console.log(`Found API key for connector ${connectorAddress}: ${connector.apiKey}`)
    return connector.apiKey
  }

  console.log(`Using default API key for connector ${connectorAddress}: ${authConfig.apiKey}`)
  return authConfig.apiKey
}
```

```json
  },
  "dataAddress": {
    "@type": "DataAddress",
    "type": "HttpData",
    "baseUrl": "http://backend-service:8080/api/products"
```


### 2. Creación de Policies

Una **Policy** define las reglas de acceso y uso de los assets usando el estándar ODRL 2.2.

#### Error Común

```
Failed to add policy: API request failed: 400 Bad Request - 
[{"message":"Failed to resolve policy type: Rule does not contain any action field. 
Expected one of: http://www.w3.org/ns/odrl/2/action","type":"ValidationFailure"}]
```

**Causa**: Falta el campo obligatorio `action` en la regla de la política.

#### Estructura Correcta de una Policy

```json
{
  "@context": {
    "@vocab": "https://w3id.org/edc/v0.0.1/ns/",
    "odrl": "http://www.w3.org/ns/odrl/2/"
  },
  "@type": "PolicyDefinition",
  "@id": "policy-allow-use",
  "policy": {
    "@type": "Policy",
    "permission": [
      {
        "action": "USE",
        "constraint": []
      }
    ]
  }
}
```

#### Campos Obligatorios

| Campo | Descripción | Valores |
|-------|-------------|---------|
| **`action`** | Acción permitida/prohibida | `USE`, `TRANSFER`, `READ`, `WRITE` |
| **`permission`** | Reglas de lo permitido | Array de permisos |
| **`prohibition`** | Reglas de lo prohibido | Array de prohibiciones |
| **`obligation`** | Reglas obligatorias | Array de obligaciones |

#### Ejemplos de Policies

**Policy simple sin restricciones:**

```json
{
  "@context": {
    "@vocab": "https://w3id.org/edc/v0.0.1/ns/",
    "odrl": "http://www.w3.org/ns/odrl/2/"
  },
  "@type": "PolicyDefinition",
  "@id": "allow-all-policy",
  "policy": {
    "@type": "Policy",
    "permission": [
      {
        "action": "USE"
      }
    ]
  }
}
```

**Policy con restricción de BPN:**

### 3. Creación de Contract Definitions

Una **Contract Definition** vincula assets con policies para crear ofertas contractuales.

#### Estructura de un Contract Definition

```json
{
  "@context": {
    "@vocab": "https://w3id.org/edc/v0.0.1/ns/"
  },
  "@type": "ContractDefinition",
  "@id": "contract-def-01",
  "accessPolicyId": "allow-all-policy",
  "contractPolicyId": "allow-all-policy",
  "assetsSelector": [
    {
      "operandLeft": "@id",
      "operator": "=",
      "operandRight": "asset-01"
    }
  ]
}
```

#### Campos

| Campo | Descripción | Requerido |
|-------|-------------|-----------|
| **`@id`** | ID único del contrato | Sí |
| **`accessPolicyId`** | Policy para acceso | Sí |
| **`contractPolicyId`** | Policy del contrato | Sí |
| **`assetsSelector`** | Selector de assets | Sí |

#### Ejemplo via API

```bash
curl -k -X POST https://edc-mass-control.51.178.94.25.nip.io/management/v2/contractdefinitions \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: mass-api-key-change-in-production" \
  -d '{
    "@context": {
      "@vocab": "https://w3id.org/edc/v0.0.1/ns/"
    },
    "@type": "ContractDefinition",
    "@id": "product-data-contract",
    "accessPolicyId": "allow-use-policy",
    "contractPolicyId": "allow-use-policy",
    "assetsSelector": [
      {
        "operandLeft": "@id",
        "operator": "=",
        "operandRight": "product-data-asset"
      }
    ]

```
