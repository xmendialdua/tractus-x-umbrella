## 🔍 Secuencia Cronológica de Problemas y Soluciones

### **Problema 1: Proxy DIM falla con DIDs vacíos**

#### Contexto
El día anterior se había implementado un proxy (`dim-wallet-proxy`) para interceptar requests del DIM Wallet Stub y agregar VCs faltantes. Sin embargo, cuando se intentaba deshabilitar IATP (configurando DIDs vacíos), el proxy crasheaba.

#### Síntoma
```bash
# Error en logs del proxy
HTTP client exception caught for request [POST, http://dim-wallet-proxy...]
```

**Request problemático:**
```json
{
  "grantAccess": {
    "consumerDid": "",  // ← DIDs vacíos cuando IATP disabled
    "providerDid": "",
    "credentialTypes": ["MembershipCredential"]
  }
}
```

#### Causa Raíz
El proxy intentaba procesar DIDs vacíos, llamando al DIM Wallet Stub que no sabía cómo manejarlos. El stub esperaba DIDs válidos para generar tokens.

#### Solución Implementada

**Archivo modificado:** [`dim-wallet-proxy/proxy.js`](../dim-wallet-proxy/proxy.js) (líneas 169-189)

```javascript
// CHECK FOR IATP DISABLED (empty DIDs)
app.use('/api/sts', express.json(), async (req, res) => {
  console.log(`[${new Date().toISOString()}] === Intercepting STS request ===`);
  
  const hasEmptyDids = req.body.grantAccess && 
                      (req.body.grantAccess.consumerDid === "" || 
                       req.body.grantAccess.providerDid === "");
  
  if (hasEmptyDids) {
    console.log('⚠️ IATP DISABLED detected (empty DIDs) - returning dummy token');
    
    // Return dummy token - EDC no valida contenido cuando IATP está deshabilitado
    return res.status(200).json({
      token: "eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0.eyJzdWIiOiJkdW1teSIsImlzcyI6ImR1bW15IiwiZXhwIjo5OTk5OTk5OTk5fQ.",
      expiresIn: 3600
    });
  }
  
  // Si hay DIDs, procesar normalmente...
});
```

**Despliegue:**
```bash
cd dim-wallet-proxy

# Actualizar ConfigMap con código modificado
kubectl create configmap dim-wallet-proxy-code \
  --from-file=proxy.js=./proxy.js \
  -n portal --dry-run=client -o yaml | kubectl apply -f -

# Reiniciar proxy para cargar nuevo código
kubectl rollout restart deployment/dim-wallet-proxy -n portal
```

**Resultado:** ✅ Proxy ahora maneja correctamente requests con DIDs vacíos

**Incluso el endpoint de management que antes funcionaba ahora fallaba.**

#### Investigación

**Verificación de Ingress:**
```bash
kubectl get ingress -n mass-connector mass-edc-tractusx-connector-controlplane -o yaml
```

**Configuración encontrada:**
```yaml
spec:
  ingressClassName: nginx

- `/api/check/liveness` → puerto 8080
- `/api/check/readiness` → puerto 8080
- Otros endpoints del puerto 8080

```

├─────────────────────────────────────────────────┤
│                                                 │

│         ↳ /api/check/health                     │
│         ↳ /api/check/liveness                   │
│         ↳ /api/check/readiness                  │
│                                                 │

### **Problema 3: Conflicto Helm al redesplegar**

#### Contexto
Con el Ingress corregido, se intentó redesplegar los conectores para aplicar los cambios.

#### Síntoma
```bash
bash deploy-mass-connector.sh

# Error de Helm:
Error: UPGRADE FAILED: cannot patch "mass-edc-tractusx-connector-controlplane" 
with kind Deployment: 
Strategic merge patch contains invalid syntax: 
element values in setElementOrder list 
[map[name:EDC_IAM_ISSUER_ID value:did:web:ssi-dim-wallet-stub.51.178.94.25.nip.io:BPNL00000000MASS] 
 map[name:EDC_IAM_ISSUER_ID value:]] 
doesn't match $setElementOrder list: 
[map[name:EDC_IAM_ISSUER_ID]]
```

#### Causa Raíz

**Helm Strategic Merge Patch Conflict**

La variable `EDC_IAM_ISSUER_ID` estaba definida en **dos lugares**:

1. **Base chart** (`tractusx-connector`):
   ```yaml
   env:
     - name: EDC_IAM_ISSUER_ID
       value: "did:web:ssi-dim-wallet-stub.51.178.94.25.nip.io:BPNL00000000MASS"
   ```

2. **Values overlay** (`values-mass-connector.yaml`):
   ```yaml
   controlplane:
     env:
       EDC_IAM_ISSUER_ID: ""  # Intentando sobreescribir
   ```

Helm no puede hacer "strategic merge patch" cuando una misma variable aparece con valores diferentes en la lista de envs, porque **no puede determinar el orden correcto**.

**¿Por qué pasa esto?**
- Los arrays en Kubernetes se parchean usando `patchStrategy:"merge"` y `patchMergeKey:"name"`
- Helm intenta mantener el orden con `$setElementOrder`
- Si la misma `name` aparece con valores diferentes, Helm no sabe cuál prevalece

#### Solución Implementada

**No usar env vars en values overlay** - Comentarlas temporalmente

**Archivos modificados:**
- [`charts/values-mass-connector.yaml`](../charts/values-mass-connector.yaml) (líneas 60-72)
- [`charts/values-ikln-connector.yaml`](../charts/values-ikln-connector.yaml) (líneas 60-72)

```yaml
controlplane:
  env:
    TX_IAM_IATP_CREDENTIALSERVICE_URL: http://dim-wallet-proxy.portal.svc.cluster.local:8080/api
    EDC_JSONLD_HTTPS_ENFORCE: "false"
    JAVA_TOOL_OPTIONS: "-Djavax.net.ssl.trustAll=true -Djdk.tls.client.protocols=TLSv1.2"
    
    # TESTING ONLY: Deshabilitar validación IATP
    # COMENTADO TEMPORALMENTE - Causa conflicto en Helm patch
    # EDC_IAM_ISSUER_ID: ""
    # TX_EDC_IAM_IATP_SKIP: "true"
```

**Plan alternativo (no ejecutado):**
Para aplicar estas variables después del despliegue, usar:
```bash
kubectl set env deployment/mass-edc-tractusx-connector-controlplane \
  -n mass-connector \
  EDC_IAM_ISSUER_ID="" \
  TX_EDC_IAM_IATP_SKIP="true"
```

### **Problema 5: Catalog Discovery con 401 Unauthorized**

#### Contexto
Con los conectores funcionando y endpoints saludables, se intentó realizar catalog discovery desde IKLN hacia MASS.

#### Síntoma
```bash
curl -s -X POST "http://edc-ikln-control.51.178.94.25.nip.io/management/v3/catalog/request" \
  -H "x-api-key: ikln-api-key-change-in-production" \
  -H "Content-Type: application/json" \
  -d '{
    "@context": {"@vocab": "https://w3id.org/edc/v0.0.1/ns/"},
    "counterPartyAddress": "http://edc-mass-control.51.178.94.25.nip.io/api/v1/dsp",
    "counterPartyId": "BPNL00000000MASS",
    "protocol": "dataspace-protocol-http"
  }'

# Response:
{
  "message": "Unable to complete catalog request: {\"@type\":\"dspace:CatalogError\",\"dspace:code\":\"401\",\"dspace:reason\":\"Unauthorized\"}"
}
```

**Error 401 Unauthorized** al intentar acceder al catálogo.

#### Investigación

**Verificar configuración IATP en pods:**
```bash
# IKLN
kubectl exec -n ikln-connector \
  deployment/ikln-edc-tractusx-connector-controlplane -- \
  env | grep -E "(EDC_IAM_ISSUER_ID|TX_EDC_IAM_IATP_SKIP)"

# Output:
EDC_IAM_ISSUER_ID=did:web:ssi-dim-wallet-stub.51.178.94.25.nip.io:BPNL00000002IKLN
TX_EDC_IAM_IATP_SKIP=true
```

```bash
# MASS
kubectl exec -n mass-connector \
  deployment/mass-edc-tractusx-connector-controlplane -- \
  env | grep -E "(EDC_IAM_ISSUER_ID|TX_EDC_IAM_IATP_SKIP)"

# Output:
EDC_IAM_ISSUER_ID=did:web:ssi-dim-wallet-stub.51.178.94.25.nip.io:BPNL00000000MASS
TX_EDC_IAM_IATP_SKIP=true
```

#### Causa Raíz

**IATP parcialmente habilitado**

Para **deshabilitar completamente IATP**, se requieren **ambas** configuraciones:

| Variable | Valor requerido | Valor actual | Estado |
|----------|----------------|--------------|---------|
| `EDC_IAM_ISSUER_ID` | `""` (vacío) | `did:web:...` | ❌ Incorrecto |
| `TX_EDC_IAM_IATP_SKIP` | `"true"` | `true` | ✅ Correcto |

**El problema:**
- Con `EDC_IAM_ISSUER_ID` con valor (DID), el EDC **intenta autenticación IATP**
- Aunque `TX_EDC_IAM_IATP_SKIP=true`, no es suficiente
- El conector consumer (IKLN) intenta obtener SI Token del DIM
- El provider (MASS) valida el token y rechaza con 401

**¿Por qué falla la validación?**

Basado en debugging del 9 de febrero, el DIM Wallet Stub tiene un bug:
```java
// Bug en signToken: usa BPN incorrecto
String partnerBpn = extractBpnFromBearer(authToken);  // ❌ BPN del Bearer (self)
// Debería usar:
String partnerBpn = extractBpnFromDid(request.getAudience());  // ✅ BPN del target
```

Esto genera tokens con `audience` incorrecto, causando rechazo 401.

**Flujo del error:**
```
1. IKLN prepara catalog request
2. IKLN ve EDC_IAM_ISSUER_ID con valor → activa IATP
3. IKLN solicita SI Token al DIM Wallet Stub
4. DIM genera token con bug (audience incorrecto)
5. IKLN envía request con token a MASS
6. MASS valida token → audience no coincide
7. MASS rechaza con 401 Unauthorized
```

## 💡 Lecciones Aprendidas

### Configuración IATP

**Para deshabilitar completamente IATP se requieren DOS configuraciones:**
```yaml
EDC_IAM_ISSUER_ID: ""        # ← CRÍTICO: Debe estar vacío
TX_EDC_IAM_IATP_SKIP: "true" # ← Debe ser true
```

Solo una de ellas **no es suficiente**.

---

### Helm Strategic Merge Patches

**No se puede definir la misma variable en múltiples niveles:**
- Base chart define: `EDC_IAM_ISSUER_ID=did:web:...`
- Values overlay intenta: `EDC_IAM_ISSUER_ID=""`
- **Resultado:** Error de merge patch

**Solución:** Usar `kubectl set env` post-despliegue.

---

### Ingress Endpoints en Tractus-X

Los conectores EDC exponen **múltiples puertos**, cada uno debe tener su entrada en Ingress:

| Endpoint | Puerto | Rutas | Propósito |
|----------|--------|-------|-----------|
| `default` | 8080 | `/api/*` | Health checks, observability |
| `protocol` | 8084 | `/api/v1/dsp` | DSP (Dataspace Protocol) |
| `management` | 8081 | `/management` | Management API |
| `public` | 8185 | `/public` | Public API (dataplane) |

**Olvidar el endpoint `default` causa 404 en health checks.**

---

### Proxy como Solución Temporal

El proxy `dim-wallet-proxy` es útil para:
- ✅ Testing rápido
- ✅ Workarounds temporales
- ✅ Agregar VCs faltantes

**Pero NO es adecuado para:**
- ❌ Producción (firma insegura)
- ❌ Solución a largo plazo
- ❌ Ambientes regulados

**Evolución recomendada:**
```
Testing:     dim-wallet-proxy (actual)
              ↓
Pre-prod:    Managed Identity Wallet
              ↓
Producción:  Managed Identity Wallet + HSM
```
