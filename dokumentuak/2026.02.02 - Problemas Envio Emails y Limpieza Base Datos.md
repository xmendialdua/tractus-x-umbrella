### 13:00 - Problema 3: smtp4dev sin Ingress

**Síntoma:** No se puede acceder a `http://smtp4dev.51.178.94.25.nip.io/` (404 Not Found)

**Causa:** El chart `smtp4dev` no incluye template de Ingress por defecto.

**Solución:** Crear template personalizado en umbrella chart:

**Archivo creado:** `charts/umbrella/templates/smtp-ingress.yaml`
```yaml
{{ if index .Values "smtp4dev" "enabled" }}
{{- if .Values.smtp4dev.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: smtp4dev-ingress
  labels:
    name: smtp4dev-ingress
  {{- with .Values.smtp4dev.ingress.annotations }}
  annotations:
    {{- toYaml . | nindent 4 }}
  {{- end }}
spec:
  {{- if .Values.smtp4dev.ingress.className }}
  ingressClassName: {{ .Values.smtp4dev.ingress.className }}
  {{- end }}
  rules:
  {{- if .Values.smtp4dev.ingress.hosts }}
  {{- range .Values.smtp4dev.ingress.hosts }}
  - host: {{ .host | quote }}
    http:
      paths:
      {{- range .paths }}
      - path: {{ .path }}
        pathType: {{ .pathType }}
        backend:
          service:
            name: smtp4dev
            port: 
              number: {{ $.Values.smtp4dev.ports.http }}
      {{- end }}
  {{- end }}
  {{- end }}
{{- end }}
{{- end }}
```

**Configuración en values-ovh-hosts-portal.yaml:**
```yaml
smtp4dev:
  ingress:
    enabled: true
    className: "nginx"
    hosts:
      - host: smtp4dev.51.178.94.25.nip.io

          - path: /
            pathType: Prefix
```

## 🎯 Lecciones Aprendidas

### 1. Email Asíncrono - No Inmediato

**Aprendido:** Los emails NO se envían inmediatamente al invitar.

**Flujo correcto:**
```
Portal UI → administration-service → BD (invitación pendiente)
                                      ↓
                          processes-worker (cada 5 min) → SMTP → smtp4dev
```

**Implicación:** Después de invitar, hay que **esperar hasta 5 minutos** para ver el email.

---

### 2. Variable KC_SPI NO Funciona

**Intentado:**
```yaml
KC_SPI_REALM_RESTAPI_EXTENSION_DEFAULT_SSL_REQUIRED: NONE
```

**Resultado:** Nuevos realms se siguen creando con `sslRequired: "HTTPS"`

**Solución necesaria:** **Corrección manual** después de crear cada realm:
```bash
curl -X PUT ".../auth/admin/realms/idpX" \
  -d '{"realm":"idpX","sslRequired":"NONE"}'
```

---

### 3. Base de Datos Persistente Requiere Mantenimiento

**Problema:** Con persistencia, los datos de pruebas fallidas se acumulan.

**Solución:** Después de múltiples pruebas, **limpiar completamente** o tener script de limpieza.

---

### 4. Configuración SMTP via kubectl set env vs Helm

**Problema:** Aplicamos configuración SMTP con `kubectl set env` (live) en lugar de via Helm.

**Implicación:** Los cambios NO están persistidos en Helm. En próximo upgrade, se pueden perder.

**Solución correcta:** Configurar en `values-ovh-hosts-portal.yaml` y hacer `helm upgrade`.
