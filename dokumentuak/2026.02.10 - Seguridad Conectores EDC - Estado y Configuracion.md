## 🔒 Capas de Seguridad en Catena-X

La arquitectura de seguridad de Catena-X se compone de **tres capas independientes**:

### 1. SSL/TLS - Cifrado de Transporte

**Propósito:** Cifrar las comunicaciones entre conectores para prevenir ataques man-in-the-middle.

**Componentes:**
- Certificados SSL/TLS en los ingress controllers
- HTTPS en todos los endpoints públicos (DSP, Management, Data Plane)
- Validación de cadena de certificados (Certificate Authority Trust)

**Configuración relevante:**
```yaml
# Ingress TLS
ingresses:
  - enabled: true
    tls:
      enabled: true  # Habilita HTTPS
      secretName: "edc-tls-cert"

# Java SSL Configuration
env:
  EDC_JSONLD_HTTPS_ENFORCE: "true"  # Fuerza HTTPS en todas las URLs JSON-LD
  JAVA_TOOL_OPTIONS: ""  # No deshabilitar validación SSL
```

---

### 2. IATP - Identity and Trust Protocol

**Propósito:** Autenticación mutua entre conectores usando OAuth 2.0 y tokens SI (Self-Issued).

**Flujo de autenticación:**
1. Connector A solicita token SI al servicio STS (Secure Token Service)
2. STS genera token JWT firmado con clave privada del DID
3. Connector A incluye token SI en headers de mensajes DSP
4. Connector B valida token usando clave pública del DID
5. Si válido, procesa la petición

**Componentes:**
- **STS (Secure Token Service):** Genera tokens SI
- **DID (Decentralized Identifier):** Identidad única del participante (`did:web:...`)
- **Trusted Issuers:** Lista de DIDs confiables

**Configuración relevante:**
```yaml
iatp:
  id: did:web:ssi-dim-wallet-stub.51.178.94.25.nip.io:BPNL00000000MASS
  trustedIssuers:
    - did:web:ssi-dim-wallet-stub.51.178.94.25.nip.io:BPNL00000003CRHK
  sts:
    dim:
      url: http://dim-wallet-proxy.portal.svc.cluster.local:8080/api/sts
    oauth:
      token_url: http://dim-wallet-proxy.portal.svc.cluster.local:8080/oauth/token

env:
  TX_EDC_IAM_IATP_SKIP: "false"  # Habilita validación IATP
  EDC_IAM_ISSUER_ID: "did:web:..."  # DID del conector
```

---

### 3. Verifiable Credentials (VCs) - Autorización por Políticas

**Propósito:** Control de acceso basado en credenciales verificables (permisos y certificaciones).

**Tipos de VCs en Catena-X:**
- **MembershipCredential:** Certifica que el participante es miembro del dataspace
- **FrameworkAgreement:** Acuerdo marco firmado (ej: DataExchangeGovernance:1.0)
- **UsagePurpose:** Propósito declarado del uso de datos (ej: cx.core.industrycore:1)
- **BPN:** Business Partner Number (identificación única)

**Validación:**
- Las VCs se validan durante la negociación de contratos
- Las políticas ODRL definen qué VCs se requieren
- El Credential Service (DIM Wallet) proporciona las VCs del participante

**Ejemplo de política:**
```json
{
  "@type": "PolicyDefinition",
  "@id": "cx-policy-test-002",
  "policy": {
    "odrl:permission": [{
      "odrl:constraint": [
        {
          "odrl:leftOperand": "Membership",
          "odrl:operator": "eq",
          "odrl:rightOperand": "active"
        },
        {
          "odrl:leftOperand": "FrameworkAgreement",
          "odrl:operator": "eq",
          "odrl:rightOperand": "DataExchangeGovernance:1.0"
        },
        {
          "odrl:leftOperand": "UsagePurpose",
          "odrl:operator": "eq",
          "odrl:rightOperand": "cx.core.industrycore:1"
        }
      ]
    }]
  }
}
```

## ⚠️ Errores Encontrados Relacionados con Seguridad

### 1. Error PKIX - Certificado SSL No Válido

**Mensaje de error:**
```
org.eclipse.edc.http.spi.EdcHttpClientException: (certificate_unknown) 
PKIX path building failed: sun.security.provider.certpath.SunCertPathBuilderException: 
unable to find valid certification path to requested target
```

**Causa raíz:**
- Se estaba usando `https://` en `counterPartyAddress` 
- Los conectores están configurados con DSP endpoints HTTP (no HTTPS)
- Ingress no tiene certificados TLS configurados (`tls.enabled: false`)

**Solución aplicada:**
- Cambiar todas las URLs DSP a HTTP
- Usar hostname correcto: `edc-mass-control` (no `edc-mass-dsp`)

**Ejemplo:**
```bash
# ❌ INCORRECTO
"counterPartyAddress": "https://edc-mass-dsp.51.178.94.25.nip.io/api/v1/dsp"

# ✅ CORRECTO
"counterPartyAddress": "http://edc-mass-control.51.178.94.25.nip.io/api/v1/dsp"
```

---

### 2. Negociaciones Atascadas en Estado REQUESTED

**Síntomas:**
- Contract negotiations se quedan en estado `REQUESTED` indefinidamente
- `contractAgreementId` permanece `null`
- No progresa a estados `AGREEING` → `AGREED` → `FINALIZED`

**Causa identificada:**
- IATP deshabilitado (`TX_EDC_IAM_IATP_SKIP=true`)
- Problema histórico con dim-wallet-stub (bug en `audienceDid` vs `audienceBPN`)
- Posible falta de VCs en respuestas del Credential Service

**Estado actual:**
- Problema corregido en dim-wallet-proxy
- Negociaciones atascadas fueron terminadas y eliminadas
- Se requiere nueva negociación para validar fix completo

---

### 3. Policy Filtering - Assets No Visibles en Catálogo

**Síntoma:**
- Asset `test-simple-asset` no aparecía en catálogo para consumer IKLN
- Solo `masspdf` era visible

**Causa raíz:**
- `accessPolicyId` configurado con política restrictiva (`cx-policy-test-002`)
- Política requería 3 VCs: Membership + FrameworkAgreement + UsagePurpose
- EDC filtra assets durante construcción del catálogo si consumer no cumple access policy

**Solución aplicada:**
```bash
# Separar políticas por propósito:
accessPolicyId: "access-policy-minimal"     # Sin restricciones (permite ver en catálogo)
contractPolicyId: "cx-policy-test-002"      # Restrictiva (valida VCs al negociar)
```

**Lección aprendida:**
- `accessPolicyId`: Controla VISIBILIDAD en catálogo
- `contractPolicyId`: Controla AUTORIZACIÓN al negociar contrato

---

### 4. Transfer Error - URL Incorrecta en UI

## 🛡️ Cambios Necesarios para Producción

### CRÍTICO - Seguridad SSL/TLS

#### 1. Obtener Certificados SSL Válidos

**Opciones:**
- **Let's Encrypt** (gratis, renovación automática via cert-manager)
- **Certificado comercial** (DigiCert, GlobalSign, etc.)
- **Certificado interno** si hay PKI corporativa

**Recomendación:** Usar cert-manager con Let's Encrypt para OVH:

```bash
# Instalar cert-manager
helm repo add jetstack https://charts.jetstack.io
helm repo update
helm install cert-manager jetstack/cert-manager \
  --namespace cert-manager \
  --create-namespace \
  --set installCRDs=true

# Crear ClusterIssuer para Let's Encrypt
kubectl apply -f - <<EOF
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: admin@mondragonassembly.com
    privateKeySecretRef:
      name: letsencrypt-prod
    solvers:
    - http01:
        ingress:
          class: nginx
EOF
```

#### 2. Actualizar Configuración de Conectores

**Archivo:** `charts/values-mass-connector.yaml` y `charts/values-ikln-connector.yaml`

```yaml

  controlplane:
    env:
      # ✅ HABILITAR: Forzar HTTPS en JSON-LD

      # ✅ ELIMINAR: Opciones que deshabilitan SSL
      # JAVA_TOOL_OPTIONS: "-Djavax.net.ssl.trustAll=true"  # ELIMINAR ESTA LÍNEA
```

### BAJO - Mejoras Adicionales

#### 1. Secrets Management

**Actual:** Passwords hardcodeados en values-*.yaml

**Mejora:** Usar Kubernetes Secrets o Vault:

```bash
# Crear secret para MASS
kubectl create secret generic mass-edc-secrets \
  -n mass-connector \
  --from-literal=postgres-password='STRONG_PASSWORD_HERE' \
  --from-literal=api-key='STRONG_API_KEY_HERE' \
  --from-literal=dim-client-secret='CLIENT_SECRET_HERE'

# Referenciar en values.yaml
postgresql:
  auth:
    existingSecret: "mass-edc-secrets"
    secretKeys:
      adminPasswordKey: "postgres-password"
```

#### 2. Network Policies

Restringir comunicación entre pods:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: edc-controlplane-policy
  namespace: mass-connector
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/component: controlplane
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: nginx-ingress
    ports:
    - protocol: TCP
      port: 8081  # Management
    - protocol: TCP
      port: 8084  # DSP
  egress:
  - to:
    - namespaceSelector:
        matchLabels:
          name: portal
    ports:
    - protocol: TCP
      port: 8080  # dim-wallet-proxy
```
