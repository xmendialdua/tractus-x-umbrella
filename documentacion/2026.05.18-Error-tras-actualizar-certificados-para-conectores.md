## 🔍 Contexto y Problema Original

### Problema en Proyecto iFlex

Según se documenta en `/home/xmendialdua/projects/assembly/iflex/20260518-Error-conexion-no-privada.md`, el **certificado de la Certificate Authority (CA) interna** utilizado por cert-manager para firmar todos los certificados TLS del cluster **expiró el 14 de mayo de 2026 a las 11:18:13 GMT**.

Este certificado CA era utilizado para:
- Firmar certificados TLS de aplicaciones web (como `ds-management`)
- Generar certificados para los conectores EDC (control planes y data planes)
- Establecer confianza entre los servicios del cluster

### Acción Tomada

Para resolver el problema del certificado CA expirado:
1. Se generó un **nuevo certificado CA** válido desde el 18 de mayo de 2026 hasta el 15 de mayo de 2036
2. Se actualizó el secret `root-secret` en el namespace `umbrella` con el nuevo CA
3. Se regeneraron los certificados TLS de los servicios afectados

### Consecuencia Inesperada

Tras la renovación del certificado CA, los **conectores EDC comenzaron a fallar** al intentar comunicarse entre sí para consultar catálogos de datos.

### Hipótesis Inicial

El error 502 sugería que el conector IKLN no podía establecer una conexión TLS válida con el conector MASS debido a un problema de confianza en los certificados.

## 🔬 Causa Raíz del Problema

### Análisis Realizado

#### 1. Verificación de Mecanismo de Certificados

Se verificó que ambos conectores EDC tienen un **mecanismo para cargar certificados personalizados**:

```bash
kubectl get pod ikln-edc-controlplane-8496565485-sktxq -n umbrella \
  -o jsonpath='{.spec.initContainers[*].name}'
```

**Resultado:**
```
custom-cacerts
```

**Observación:** Los conectores tienen un init container `custom-cacerts` que se ejecuta antes del contenedor principal.

#### 2. Análisis del Init Container

```bash
kubectl get pod ikln-edc-controlplane-8496565485-sktxq -n umbrella \
  -o jsonpath='{.spec.initContainers[?(@.name=="custom-cacerts")]}' | jq '.'
```

**Funcionamiento del Init Container:**

1. Copia el truststore de Java por defecto (`cacerts`)
2. Lee certificados desde el volumen `/cacerts` montado desde un ConfigMap
3. Importa cada certificado `.crt` o `.pem` al truststore
4. Guarda el truststore modificado en `/workdir` (volumen compartido con el contenedor principal)

**Comando ejecutado:**
```bash
cp /opt/java/openjdk/lib/security/cacerts /workdir/
find /cacerts -type f \( -iname \*.crt -o -iname \*.pem \) -exec echo "{}" \; | while read PEM_FILE_PATH; do
  PEM_FILE=${PEM_FILE_PATH##*/}
  ALIAS=${PEM_FILE%.*}
  echo "adding ${PEM_FILE} with alias ${ALIAS} to cacerts ..."
  keytool -import -noprompt -trustcacerts -alias ${ALIAS} \
    -file ${PEM_FILE_PATH} -keystore /workdir/cacerts -storepass changeit
done
```

#### 3. Identificación del ConfigMap

```bash
kubectl get pod ikln-edc-controlplane-8496565485-sktxq -n umbrella \
  -o jsonpath='{.spec.volumes[?(@.name=="custom-cacertificates")]}' | jq '.'
```

**Resultado:**
```json
{
  "configMap": {
```

### Conclusión del Diagnóstico

**Causa raíz identificada:**

Los **ConfigMaps** `ikln-edc-custom-cacerts` y `mass-edc-custom-cacerts` contenían el **certificado CA antiguo que expiró el 14 de mayo de 2026**.

Aunque se había renovado el certificado CA en el secret `root-secret` y se habían regenerado los certificados TLS de los conectores:
- Los certificados TLS de los conectores fueron firmados con el **nuevo CA** (válido)
- El truststore de Java en los conectores contenía el **antiguo CA** (expirado)
- Los conectores no confiaban en los certificados presentados por sus peers porque no podían validarlos con su CA de confianza

**Diagrama del problema:**

```

┌─────────────────────┐                 ┌─────────────────────┐
```

## ✅ Solución Implementada

### Paso 1: Exportar el Nuevo Certificado CA

```bash
export KUBECONFIG=/home/xmendialdua/projects/assembly/tractus-x-umbrella/kubeconfig.yaml

# Exportar certificado CA a archivo temporal
kubectl get secret root-secret -n umbrella \
  -o jsonpath='{.data.ca\.crt}' | base64 -d > /tmp/new-ca.crt

# Verificar el certificado
openssl x509 -in /tmp/new-ca.crt -text -noout | grep -E "Subject:|Issuer:|Not Before|Not After"
```

**Salida:**
```
Issuer: C = DE, ST = Some-State, O = CX, CN = 51.178.94.25.nip.io
    Not Before: May 18 08:45:28 2026 GMT
    Not After : May 15 08:45:28 2036 GMT
Subject: C = DE, ST = Some-State, O = CX, CN = 51.178.94.25.nip.io
```

### Paso 2: Actualizar ConfigMaps con el Nuevo Certificado

**Actualizar ConfigMap de IKLN:**
```bash
kubectl create configmap ikln-edc-custom-cacerts \
  --from-file=tractus-x-ca.crt=/tmp/new-ca.crt \
  -n umbrella \
  --dry-run=client -o yaml | kubectl apply -f -
```

**Resultado:**
```
Warning: resource configmaps/ikln-edc-custom-cacerts is missing the 
kubectl.kubernetes.io/last-applied-configuration annotation
configmap/ikln-edc-custom-cacerts configured
```

**Actualizar ConfigMap de MASS:**
```bash
kubectl create configmap mass-edc-custom-cacerts \
  --from-file=tractus-x-ca.crt=/tmp/new-ca.crt \
  -n umbrella \
  --dry-run=client -o yaml | kubectl apply -f -
```

**Resultado:**
```
configmap/mass-edc-custom-cacerts configured
```

### Paso 3: Reiniciar los Pods de los Conectores

Para que los init containers vuelvan a ejecutarse y carguen el nuevo certificado:

```bash
# Reiniciar controlplane de IKLN
kubectl rollout restart deployment ikln-edc-controlplane -n umbrella

# Reiniciar controlplane de MASS

# Esperar a que se complete el rollout
```

### Paso 4: Actualizar Archivos de Valores de Helm

Para mantener la **consistencia** entre el estado del cluster y los archivos de configuración declarativos, se actualizaron los certificados CA embebidos en los archivos de valores:

**Archivos actualizados:**
- `charts/dataspace-connector-bundle/values-ikln-connector.yaml`
- `charts/dataspace-connector-bundle/values-mass-connector.yaml`

**Sección modificada:**
```yaml

  customCaCerts:
    tractus-x-ca.crt: |
      -----BEGIN CERTIFICATE-----
      MIIFZjCCA06gAwIBAgIQIEs6H/ERoJ4Hey3t0GabcjANBgkqhkiG9w0BAQsFADBN
      # ... (nuevo certificado CA válido hasta 2036)
```

**Nota:** Esta actualización es importante para que en futuros despliegues con Helm, los conectores reciban automáticamente el certificado CA correcto.

### 2. Documentación de Procedimiento de Renovación

Cuando se renueve el certificado CA en el futuro, seguir estos pasos:

1. **Renovar el certificado CA** en `root-secret`
2. **Actualizar los ConfigMaps** de los conectores (como en este documento)
3. **Reiniciar los deployments** de los conectores
4. **Actualizar los archivos de valores** de Helm
5. **Verificar** la conectividad entre conectores
6. **Documentar** la renovación con fecha y nuevas fechas de expiración

### 3. Script Automatizado de Actualización

Se recomienda crear un script que automatice la actualización de certificados:

```bash
cat > /usr/local/bin/update-edc-ca-certs.sh << 'EOF'
#!/bin/bash
set -e

export KUBECONFIG=/home/xmendialdua/projects/assembly/tractus-x-umbrella/kubeconfig.yaml

echo "=== Actualizando certificados CA de conectores EDC ==="

# 1. Exportar nuevo certificado
echo "1. Exportando nuevo certificado CA..."
kubectl get secret root-secret -n umbrella \
  -o jsonpath='{.data.ca\.crt}' | base64 -d > /tmp/new-ca.crt

# 2. Actualizar ConfigMaps
echo "2. Actualizando ConfigMaps..."
kubectl create configmap ikln-edc-custom-cacerts \
  --from-file=tractus-x-ca.crt=/tmp/new-ca.crt \
  -n umbrella --dry-run=client -o yaml | kubectl apply -f -

kubectl create configmap mass-edc-custom-cacerts \
  --from-file=tractus-x-ca.crt=/tmp/new-ca.crt \
  -n umbrella --dry-run=client -o yaml | kubectl apply -f -

# 3. Reiniciar conectores
echo "3. Reiniciando conectores..."
kubectl rollout restart deployment ikln-edc-controlplane -n umbrella
kubectl rollout restart deployment mass-edc-controlplane -n umbrella

# 4. Esperar a que se completen los rollouts
echo "4. Esperando a que se completen los rollouts..."
kubectl rollout status deployment ikln-edc-controlplane -n umbrella --timeout=5m
kubectl rollout status deployment mass-edc-controlplane -n umbrella --timeout=5m

# 5. Verificar
echo "5. Verificando importación de certificados..."
sleep 5
IKLN_POD=$(kubectl get pods -n umbrella -l app.kubernetes.io/name=tractusx-connector,app.kubernetes.io/component=controlplane,app.kubernetes.io/instance=ikln-edc --no-headers | awk '{print $1}')
kubectl logs $IKLN_POD -n umbrella -c custom-cacerts | tail -2

# Limpiar
rm -f /tmp/new-ca.crt

echo ""
echo "✅ Actualización completada"
echo ""
echo "ACCIÓN MANUAL REQUERIDA:"
echo "- Actualizar charts/dataspace-connector-bundle/values-ikln-connector.yaml"
echo "- Actualizar charts/dataspace-connector-bundle/values-mass-connector.yaml"
echo "- Probar la consulta de catálogos en ds-management"
EOF

chmod +x /usr/local/bin/update-edc-ca-certs.sh
```

## ✅ Conclusión

El error se debió a un **desfase entre el certificado CA renovado** (almacenado en `root-secret`) y los **certificados CA en los ConfigMaps** de los conectores (que contenían el certificado expirado).

La solución consistió en:
1. Actualizar los ConfigMaps con el nuevo certificado CA
2. Reiniciar los pods para que cargaran el nuevo certificado
3. Actualizar los archivos de valores de Helm para mantener consistencia

El problema está **totalmente resuelto** y se han establecido procedimientos para prevenir situaciones similares en el futuro.

**Lección aprendida:** Al renovar certificados CA, verificar que todos los componentes que dependen de ellos (no solo los certificados TLS firmados) sean actualizados en consecuencia.
